# Реестр технологий RAG

Единый источник фактов о технологиях RAG. Все представления портала читают данные
только отсюда. Реестр хранится в каталоге `data/` как версионируемые файлы: это и
есть база данных проекта.

Версия схемы: 1.0.0 · Основание: `governance/DECISIONS.md`, ADR-003 и ADR-004.

## Почему файлы, а не база данных

Портал живёт на бесплатном статическом хостинге и обновляется без участия
человека. Бесплатная управляемая база на выбранной площадке истекает через
тридцать дней после создания, то есть требует ежемесячного вмешательства — ровно
того, чего проект избегает.

Файлы под управлением системы контроля версий дают даром то, что в базе пришлось
бы реализовывать отдельно:

| Требование | Как выполняется |
|---|---|
| свидетельства только добавляются | коммит неизменяем по определению |
| у каждого изменения есть происхождение | история правок по файлу |
| состояние на произвольную дату | любая ревизия дерева |
| утверждение изменений человеком | запрос на слияние |
| открытые данные для читателя | файл уже машиночитаем и скачивается по ссылке |

Схема ниже совпадает по составу полей со схемой прежних таблиц, поэтому импорт в
реляционную базу или в аналитический движок остаётся доступен, если понадобится.

## Раскладка

```
data/
  technologies/<id>.json     факты о технологии, файл на запись
  evidence/YYYY-MM.jsonl     свидетельства, только добавление, помесячно
  metrics/YYYY.jsonl         временные ряды показателей внимания и распространённости
  levels/history.jsonl       журнал изменений уровня зрелости
  manual_evidence.jsonl      свидетельства, вводимые человеком
```

Раскладка выбрана так, чтобы ежедневное обновление затрагивало минимум файлов.
Изменение одной технологии меняет один файл, поэтому различия читаются глазом, а
история по конкретной записи остаётся обозримой. Закрытый месяц свидетельств
больше никогда не переписывается.

### `technologies/<id>.json` — факты

| Поле | Тип | Описание |
|---|---|---|
| `id` | строка | устойчивый идентификатор в нижнем регистре, не меняется после создания |
| `name` | строка | каноническое имя |
| `aliases` | список строк | написания для дедупликации |
| `kind` | строка | род объекта: `paradigm`, `architecture`, `technique`, `tool`, `artifact` |
| `family` | строка | семейство в классификации предметной области |
| `groups` | список строк | страты измерений A–G, к которым относится вклад |
| `configuration` | объект | значения измерений; главное поле для сравнения |
| `residual` | список строк | механизмы, не выразимые схемой |
| `core_idea` | строка | один-два предложения фактического содержания, язык-нейтрально |
| `prose_id` | строка | связь с локализованной прозой карточки |
| `first_published` | строка | год и месяц первой публикации |
| `links` | список объектов | источники: адрес, род, метка, состояние проверки, дата проверки |

Длинные тексты в этот файл не попадают: проза живёт в ресурсах локализации и
связывается через `prose_id` (принцип K3).

### `evidence/YYYY-MM.jsonl` — свидетельства

Одна запись в строке: `technology_id`, `type`, `value`, `source`, `fetched_at`,
`obtained_by`, `verified`. Допустимые типы: публикация, независимое
воспроизведение, состояние репозитория, успешная сборка и запуск, присутствие во
фреймворке, загрузки пакета, промышленное применение, число независимых
поставщиков.

Свидетельство никогда не перезаписывается. Изменение уровня всегда объяснимо
перечнем свидетельств, доступных на момент вычисления.

### `manual_evidence.jsonl` — то, чего нет в машиночитаемом виде

Открытые индексы покрывают не всё. Публикации на площадках, работающих без
цифровых идентификаторов, промышленное применение и независимые воспроизведения
попадают в реестр только через этот файл. Формат совпадает с форматом
свидетельств, поле способа получения всегда указывает на человека, а ссылка на
подтверждение обязательна.

Это не лазейка, а признание границы: без такого пути отраслевой приём, описанный
заметкой поставщика и применяемый повсеместно, оказался бы ниже препринта,
который никто не воспроизвёл. Происхождение при этом остаётся видимым: в
интерфейсе такие свидетельства отличимы от собранных автоматически.

### `metrics/YYYY.jsonl` — временные ряды

Одна запись в строке: `technology_id`, `metric`, `value`, `measured_at`,
`source`. Это единственная часть реестра, растущая линейно со временем, поэтому
для неё действует политика уплотнения: ряды старше двадцати четырёх месяцев
прореживаются до одной точки в месяц.

### `levels/history.jsonl` — журнал уровней

Одна запись в строке: `technology_id`, `level`, `confidence`, `evidence_basis`,
`rule_version`, `computed_at`, `evidence_snapshot`. Запись добавляется **только
при изменении** уровня, а не при каждом пересчёте, поэтому журнал остаётся
коротким и читается как хроника.

Поле `evidence_basis` различает вычисленный уровень и введённый человеком: для
промышленной эксплуатации и отраслевого стандарта машиночитаемого источника не
существует, и это не маскируется под вычисление.

## Производные артефакты

Из реестра детерминированно собираются файлы, которые читает портал:

```
public/data/
  map.json        точки карты зрелости, полосы уровней и стратов
  registry.json   таблица реестра целиком, отбор идёт на клиенте
  changes.json    хроника изменений со ссылками на свидетельства
  stats.json      сводка: распределение по уровням, покрытие, свежесть
  feed.xml        лента хроники
```

Артефакты пересобираются целью `make artifacts` и проверяются целью
`make validate`: схема, разрешимость ссылок, отсутствие чисел без происхождения.

## Соглашения

**Идентификаторы.** Только строчные латинские буквы, цифры и подчёркивание.
Идентификатор не меняется после создания, поскольку на него ссылаются карточки и
внешние цитирования. Продукт с владельцем получает префикс владельца.

**Рода объектов.** Парадигма ограничивает значения измерений, не фиксируя полную
конфигурацию. Архитектура задаёт полную или почти полную конфигурацию. Техника
задаёт значение одного измерения. Инструмент реализует часть конструктора и не
является точкой конфигурационного пространства. Артефакт оценки служит для
измерения.

Сравнение уровней между родами вводит в заблуждение: техника попадает во
фреймворк одной функцией, а полная архитектура проходит тот же путь заметно
труднее. Поэтому род объекта показывается всегда и участвует в отборе.
