# STAGE — Исполняемый движок поверх схемы измерений

> Новый движок RAG, собираемый из значений измерений. Пишется с чистого листа:
> прежний удалён вместе с отменённой моделью.

Версия: 1.0.0 (спека, реализация не начата) · Зависит от: решения о назначении
движка (см. развилку ниже).

## SPECIFY

### Развилка, которую нужно закрыть до начала

Прежний движок исполнял конфигурации и служил двум целям сразу: был предметом
исследования и инструментом. Новый нужно определить точнее, потому что от ответа
зависит объём на порядок.

| Прочтение | Что строится | Оценка |
|---|---|---|
| **Иллюстрация** | движок собирает конфигурацию и отвечает на запрос по небольшому корпусу; нужен, чтобы схема была не только описанием | недели |
| **Испытуемый** | движок исполняет конфигурации достаточно точно, чтобы измерять их и сравнивать | месяцы, и упирается в стенд |
| **Продукт** | движок пригоден для встраивания в чужие системы | отдельная программа работ |

Спека написана для первого прочтения. Второе и третье требуют переработки
раздела объёма.

### Цель

Схема измерений сейчас описательна: она позволяет сравнивать технологии, но
проверить её исполнимость нечем. Движок, собирающий работающую систему из
значений измерений, эту проверку даёт: измерение, для которого нельзя написать
компонент, — не измерение, а обозначение.

### Объём

**Входит:** исполнение конфигурации по измерениям страт A–E; проверка
допустимости по Φ перед сборкой; след выполнения с указанием, какое измерение
какой шаг породило; небольшой корпус для проверки.

**Не входит:** страты F и G. Эволюция состояния и оболочка ограничений меняют
саму программу, а не её конфигурацию, и требуют иного устройства. Внешние
хранилища и модели: движок работает на заглушках, иначе он тянет за собой
инфраструктуру, которой у портала нет.

### Функциональные требования

- **FR-1.** Сборка принимает `Configuration` и отвергает недопустимую по Φ до
  начала работы, а не в середине.
- **FR-2.** Каждому значению измерения соответствует ровно один компонент;
  отсутствие компонента для значения обнаруживается тестом, а не при запуске.
- **FR-3.** След выполнения указывает, какое измерение породило шаг: это
  единственный способ проверить, что конфигурация действительно исполняется, а
  не игнорируется.
- **FR-4.** Движок не публикуется на портале и в его сборку не входит.
- **FR-5.** Значения, для которых компонент не написан, помечены в реестре
  как неисполнимые, а не выдаются за работающие.

### Критерии приёмки

- **AC-1.** Каждая конфигурация из реестра либо исполняется, либо явно отклонена
  с указанием измерения, для которого нет компонента.
- **AC-2.** Две различающиеся конфигурации дают различные следы выполнения.
- **AC-3.** Движок работает без сети и без внешних служб.

## PLAN

1. Контракт компонента: вход, выход, привязка к измерению и значению.
2. Компоненты для значений, встречающихся в реестре чаще всего.
3. Сборка по конфигурации с проверкой Φ и следом выполнения.
4. Проверка исполнимости всех конфигураций реестра.

## Замечания к реализации

Прежний движок доступен по метке `engine-v0-7axes`. Его адаптеры хранилищ и
переранжировщиков переиспользуемы по существу, но заимствовать оттуда следует
устройство, а не код: он организован вокруг отменённой модели, и перенос принесёт
её словарь обратно, чего не допустит сторож `test_no_legacy_vocabulary.py`.

Главная опасность работы — незаметное превращение иллюстрации в продукт. Признак,
по которому это видно: появление требований к производительности и к внешним
хранилищам. Как только они появляются, следует остановиться и вернуться к
развилке.
